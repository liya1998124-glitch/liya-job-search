# 搜岗与评分

## 从候选到核验

1. 用职能同义词、核心职责、城市和行业构造搜索词。从用户指定的平台、公司招聘页、公开招聘平台收集候选。首轮可先核验 5 个，按反馈和准确性扩量。新发布优先，发布时间与更新时间分别记录，缺失则标未知。
2. 先核实具体公司和具体岗位的对应关系。比对原始 JD 或用户提供的平台详情中的公司、职位、地点、薪资和职责。聚合摘要只能提供搜索线索。职位页可打开但是否仍在招未知时标待核实。官方明确关闭标失效。来源冲突时记录各版本，待复核。
3. 优先按原岗位 ID 去重。没有 ID 时用公司主体、职位、城市及职责比对，保留最完整证据。检查已投递、已沟通及用户排除记录。相似职位有可能属于不同团队，无法确认时保留关联。
4. 对工资区分固定底薪、绩效、佣金和总包，明确币种和计薪周期。仅在有证据时确认单双休、排班、远程和签约方式。明确不符合硬条件则排除，硬条件未知则先核验。

## 三个独立评分

- **岗位匹配度**默认权重为职责和技能 35、职级及经验 25、固定薪资及总包 15、地点及办公方式 10、工作制度及用工条件 10、行业迁移 5。按证据给各维度 0%、50% 或 100% 的权重，分别代表明确不符、部分满足或充分满足。未知单列。对已知维度归一到 100 并同时显示覆盖权重。覆盖不足 70% 标暂评，覆盖为零标待评。硬门槛单列，分数不覆盖硬门槛。按用户优先级调整权重时说明并在同批次保持一致。
- **岗位数据可信度**按原始职位证据 40、当前招聘状态 25、关键字段一致及完整 25、发布时间可核验 10 计。各项按充分、部分、无有效证据计满分、半分或零分，注明是资料缺失还是证据冲突。聚合摘要不得单独支撑可投递结论。
- **公司可信度**按公司核验参考计算。三个分数并排给出，每个列出主要加扣分、证据和待确认项。

建议优先投递时，需要硬条件有证据、岗位真实性可靠、适配理由具体且无足以暂停的已核实风险。重要信息缺失时写“先确认”，附一两句可直接问招聘方的问题。明确失效、硬条件不符或风险高时给出相应结论和依据。

候选表至少含公司、岗位、城市、薪资口径、工作制度、发布时间、原链接与访问状态、三项评分、推荐理由、风险、投递建议和下一步。候选不足时交付实际核验结果。
